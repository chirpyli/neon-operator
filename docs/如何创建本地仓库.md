
集群共 4 个节点（slpc 为 control-plane + 当前宿主机，node1-3 为 worker），运行时统一为 containerd。下面给出完整的本地私有仓库搭建步骤。

---

## 本地私有镜像仓库搭建指南

### 架构

```
宿主机 (slpc 192.168.232.128)
├── Docker Registry :5000          ← 私有仓库
├── docker push → registry         ← 推送 Neon Operator 镜像
└── kubectl apply                  ← 部署/更新

集群节点 (node1-3)
└── containerd pull 192.168.232.128:5000/...  ← 拉取镜像
```

---

### 第一步：启动 Docker Registry

```bash
# 创建数据持久化目录
sudo mkdir -p /opt/registry/{data,auth,certs}

# 创建 htpasswd 用户（用户名: admin, 执行后输入密码）
sudo apt install -y apache2-utils   # 如果没有 htpasswd
sudo htpasswd -Bc /opt/registry/auth/htpasswd admin

# 启动 Registry（HTTP 模式，监听宿主机 IP）
docker run -d \
  --name registry \
  --restart=always \
  -p 192.168.232.128:5000:5000 \
  -v /opt/registry/data:/var/lib/registry \
  -v /opt/registry/auth:/auth \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_REALM=Registry Realm" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2
```

> 如果不需要鉴权，删除 auth 相关的 3 行参数即可。

验证 Registry 运行：

```bash
curl -u admin:yourpassword http://192.168.232.128:5000/v2/_catalog
# 返回: {"repositories":[]}
```

---

### 第二步：登录并推送镜像

```bash
# 登录私有仓库
docker login 192.168.232.128:5000 -u admin -p yourpassword

# 打标签
docker tag neon-operator:latest 192.168.232.128:5000/neon/neon-operator:latest

# 推送
docker push 192.168.232.128:5000/neon/neon-operator:latest
```

---

### 第三步：配置 containerd 信任私有仓库（每个节点都需要）

containerd 默认只信任 HTTPS 仓库，需要添加 HTTP 例外。

**在每台节点上执行：**

```bash
# 1. 备份原配置
sudo cp /etc/containerd/config.toml /etc/containerd/config.toml.bak

# 2. 查看当前 registry 配置
sudo grep -A5 "registry.configs" /etc/containerd/config.toml
```

**如果配置文件中已有 `[plugins."io.containerd.grpc.v1.cri".registry]` 段**，追加以下内容：

```toml
[plugins."io.containerd.grpc.v1.cri".registry.configs."192.168.232.128:5000".tls]
  insecure_skip_verify = true

[plugins."io.containerd.grpc.v1.cri".registry.configs."192.168.232.128:5000".auth]
  username = "admin"
  password = "yourpassword"
```

**如果完全没有 registry 配置段**（containerd 2.x 新版本），新建或追加：

```toml
[plugins."io.containerd.grpc.v1.cri".registry]
  [plugins."io.containerd.grpc.v1.cri".registry.mirrors]
    [plugins."io.containerd.grpc.v1.cri".registry.mirrors."192.168.232.128:5000"]
      endpoint = ["http://192.168.232.128:5000"]
  [plugins."io.containerd.grpc.v1.cri".registry.configs]
    [plugins."io.containerd.grpc.v1.cri".registry.configs."192.168.232.128:5000".tls]
      insecure_skip_verify = true
    [plugins."io.containerd.grpc.v1.cri".registry.configs."192.168.232.128:5000".auth]
      username = "admin"
      password = "yourpassword"
```

**重启 containerd：**

```bash
sudo systemctl restart containerd
sudo systemctl status containerd
```

> **注意**：containerd v2.x（node1 上）配置路径可能不同，用 `containerd config default` 生成默认配置参照。

**一键批量配置脚本（在 control-plane 上执行）：**

```bash
for node in slpc node1 node2 node3; do
  echo "=== Configuring $node ..."
  ssh $node "sudo mkdir -p /etc/containerd"
  ssh $node << 'EOSSH'
sudo tee /etc/containerd/certs.d/192.168.232.128:5000/hosts.toml > /dev/null << 'EOF'
server = "http://192.168.232.128:5000"

[host."http://192.168.232.128:5000"]
  capabilities = ["pull", "resolve"]
  skip_verify = true

[auth]
  username = "admin"
  password = "yourpassword"
EOF
sudo systemctl restart containerd
EOSSH
  echo "=== $node done ==="
done
```

### 第四步：更新 Operator 部署

```bash
# 方式 A：直接 set image
kubectl set image deployment/neon-controller-manager -n neon \
  controller=192.168.232.128:5000/neon/neon-operator:latest

# 方式 B：更新 manager.yaml 后重新 make deploy
```

然后删除旧 Pod 让它重新拉取：

```bash
kubectl delete pod -n neon -l control-plane=controller-manager
kubectl get pods -n neon -w
```

### 常见问题排查

| 问题 | 排查命令 |
|------|------|
| containerd 拉取失败 | `sudo crictl pull 192.168.232.128:5000/neon/neon-operator:latest` |
| Registry 未启动 | `docker ps \| grep registry` |
| 网络不通 | `curl http://192.168.232.128:5000/v2/_catalog`（在各节点） |
| containerd 配置未生效 | `sudo journalctl -u containerd -n 50 --no-pager` |

### 进阶：TLS 证书版（可选）

如果要避免 HTTP 和 `insecure_skip_verify`，可以用自签证书：

```bash
# 生成自签证书
openssl req -newkey rsa:4096 -nodes -sha256 \
  -keyout /opt/registry/certs/registry.key \
  -x509 -days 365 \
  -out /opt/registry/certs/registry.crt \
  -subj "/CN=192.168.232.128"

# 重新启动 Registry（带 TLS）
docker rm -f registry
docker run -d \
  --name registry \
  --restart=always \
  -p 192.168.232.128:5000:5000 \
  -v /opt/registry/data:/var/lib/registry \
  -v /opt/registry/auth:/auth \
  -v /opt/registry/certs:/certs \
  -e "REGISTRY_HTTP_TLS_CERTIFICATE=/certs/registry.crt" \
  -e "REGISTRY_HTTP_TLS_KEY=/certs/registry.key" \
  -e "REGISTRY_AUTH=htpasswd" \
  -e "REGISTRY_AUTH_HTPASSWD_PATH=/auth/htpasswd" \
  registry:2

# 把证书分发到各节点
for node in node1 node2 node3; do
  scp /opt/registry/certs/registry.crt $node:/tmp/
  ssh $node "sudo cp /tmp/registry.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates"
done
```
